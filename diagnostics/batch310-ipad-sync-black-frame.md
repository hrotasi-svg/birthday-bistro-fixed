# 第310批次：iPad同步、黑色框架與第308火焰基準調查

## 初始範圍

本批次只處理`/store-select`。使用者回報iPad、手機、桌面顯示不一致，包含蝴蝶身體光源、火焰外圈短按、火柴頭與火焰定位；另回報goldan金幣上方黑色框架，並要求火焰回復第308批次設定。尚未將任何受控瀏覽器結論當作實體iPad驗收。

## 金幣Canvas首次量測

開發頁金幣Canvas CSS背景為`rgba(0, 0, 0, 0)`，畫布尺寸658×677。在噴灑開始前，445,466個畫布像素均為透明；噴灑開始後的第一個量測畫格有30個alpha大於0的像素，其中7個為近黑色可見像素。這表示目前黑框問題不能先歸因於容器CSS背景，而須進一步排除影片暗部被保留、`putImageData`預乘alpha／Safari合成，以及原始影片邊緣內容。

來源影片於0.7秒畫格共129,600像素，其中124,528像素luma低於13、97個為luma 13–42的暗中性像素、489個為同區間暗暖色像素。現行只刪除luma低於13的規則會保留部分壓縮後的暗色背景，這些殘留經放大與iPad Canvas合成可形成使用者所見的黑色框邊。金幣的有效暗暖邊緣也可低至luma約20，因此修復必須採用亮度、色彩飽和度與暖金／高光連通條件，而非單純提高亮度門檻，避免刪掉金屬邊緣。

第310版以暖金金屬／明亮反光像素遮罩移除121,966個來源背景像素，且Canvas CSS背景為透明、`mix-blend-mode: screen`及獨立透明合成層。實際噴灑畫格有7,634個金幣可見來源像素與12,392個暖金像素；雖原始影片仍包含81個近黑金屬邊緣畫素，screen合成不會把它們以正常模式變成黑色矩形或遮擋背景。火焰運行期定位為left 13.6562px／top -103.344px，對應回復的第308設定4.8%／-29.5%。

實際噴灑畫面檢視可見金幣影片於火焰上方保持原始動態，畫布外區透明，未看到黑色矩形、影片背景或以黑色覆蓋金幣的層。這是受控桌面運行期驗證；實體iPad Safari仍需以同一發布版確認。

第310版短按火焰後，火焰類別為藍色；蝴蝶身體光源、圓形外圈及側邊外圈均取得對應藍色直接徑向色票，且元素為`display:block`。身體光源opacity 0.96；實測火焰left 13.6562px／top -103.344px、火柴頭小光源top 56.75px，對應已回復的第308定位4.8%／-29.5%／16.2%。圓形外圈此時處於循環中的透明階段，不應以當下opacity 0誤判短按未套用色票。

同步追查另發現第309版版本探針在頁面包含inline或空src腳本時，`new URL(script.src)`會拋出`Invalid URL`，使焦點／頁面恢復的探針提早中斷。這是此前「已設定無快取卻仍不同步」的可重現程式根因之一。現已先過濾空src，並以頁面基準URL安全解析；重新載入門店頁後最新瀏覽器主控台無錯誤。

第310批次完整品質流程`pnpm test && pnpm exec tsc --noEmit && pnpm build`成功：27個測試檔、88個測試皆通過，正式前端產物為`index-C8HtV--g.js`。本地正式`/store-select`回應`Cache-Control: no-store, no-cache, must-revalidate, max-age=0`，且最新雜湊產物包含金幣透明screen合成標記。桌面1280×720、手機390×844與iPad 1024×1366視窗均已檢視，未見版面偏移或黑色矩形；這些為受控視窗驗證，實體iPad Safari短按、背景恢復與實際顯示仍須由使用者最終確認。
